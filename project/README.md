# Заявки в IT-отдел вуза

## О проекте

REST API для создания и управления заявками в IT-отделе вуза.

Система позволяет пользователям создавать заявки, указывать категорию проблемы, отслеживать статус заявки, оставлять комментарии и прикреплять файлы.

## Запуск

Нужен Docker (Docker Desktop должен быть запущен).

```bash
docker compose up --build
```

- API: http://localhost:8080
- Проверка: `curl -i localhost:8080/health` → `200 {"status":"ok"}`
- PostgreSQL снаружи доступен на порту `5433`
- Схема (`schema.sql`) и тестовые данные (`seed.sql`) применяются автоматически при первом запуске

Остановить: `Ctrl+C`, затем `docker compose down`.
Сбросить базу к исходному состоянию (после изменения схемы или seed): `docker compose down -v`.

### Запуск API без Docker (база в Docker)

```bash
docker compose up -d db
cp .env.example .env
export $(cat .env) && go run .
```

## Сущности

* `users` — пользователи системы
* `categories` — категории заявок
* `tickets` — заявки
* `comments` — комментарии к заявкам
* `attachments` — вложения к заявкам

### Коды ошибок

Тело ответа об ошибке: `{"error":"описание"}`.

* `400` — некорректный `id` в пути или невалидный JSON
* `404` — запись не найдена
* `409` — нельзя удалить пользователя или категорию, у которых есть заявки
* `422` — не прошла валидация: пустое обязательное поле, неверный статус, несуществующий `user_id` / `category_id` / `ticket_id`, повтор email или названия категории
* `500` — внутренняя ошибка сервера (подробности только в логе)

При удалении заявки ее комментарии и вложения удаляются автоматически.

## Статусы заявок

* `new` — новая заявка
* `in_progress` — заявка в работе
* `done` — заявка выполнена
